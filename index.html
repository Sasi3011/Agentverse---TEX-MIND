[ 01 ] The Problem

Why Textile Mills
Need A Brain

Textile manufacturing — from spinning to packing — suffers from cascading failures that no single model can solve. Different sensors, different physics, different failure signatures. This demands a true multi-agent architecture.

Yarn Breaks

Production stoppages & wasted raw material from yarn count variation

Fabric Defects

Holes, slubs & weft bars causing batch rejections & export quality loss

Shade Mismatch

Highest-cost rejection category — dyeing shade variation across batches

Energy Waste

High operating cost & carbon footprint from energy-intensive dyeing/drying

Water Overuse

Textile dyeing is among the most water-intensive industrial processes

Unplanned Downtime

Lost production hours from unexpected machine breakdowns

Poor Traceability

Compliance failures for GOTS, OEKO-TEX & export audit requirements

Worker Safety

Injuries & compliance risk near moving machinery on the floor

[ 02 ] The Specialist Agents

10 Agents,
Separate Files

The detailed write-ups now live in the agents/ folder as standalone files. This homepage keeps the overview, while each agent gets its own page for easier editing and demos.

01
Agent
Yarn Quality Agent

Predict yarn breaks and count variation before they cause loom stoppages

Inputs Spindle tension sensor readings, spindle speed, humidity/temperature, historical break-rate logs
Logic Time-series anomaly detection (rolling z-score / LSTM) on tension signal; flags trend deviation from healthy baseline
Output {risk_score: 0-1, predicted_break_time: minutes, affected_spindle_id}
Python scikit-learn Isolation Forest LSTM
02
Agent
Loom / Weaving Agent

Detect real-time weaving faults — missing pick, weft bar, loose ends

Inputs Loom RPM sensor, pick sensor, stoppage logs, optional camera feed
Logic Rule-based thresholding + pattern matching against known fault signatures; escalates to Defect Vision Agent for visual confirmation
Output {fault_type, loom_id, severity}
Python Rules Engine OpenCV
03
Agent
Dyeing Consistency Agent

Predict shade/color variation before a dye batch is ruined — highest-cost rejection

Inputs Dye recipe (chemical ratios), water hardness/pH, temperature-time curve, batch liquor ratio
Logic Regression model trained on recipe parameters vs. historical ΔE (color deviation); flags temperature/time curve drift
Output {shade_risk_score, deviation_parameter, recommended_correction}
Python XGBoost Regression
04
Agent
Energy Optimization Agent

Minimize kWh/kg of fabric by scheduling high-load machines intelligently

Inputs Real-time power meter data, machine load schedule, time-of-day tariff data
Logic Optimization/scheduling algorithm (LP or greedy heuristic) shifts high-load jobs to lower-tariff windows without breaking deadlines
Output {current_kwh_per_kg, optimized_schedule, projected_savings}
Python OR-Tools PuLP
05
Agent
Water & Effluent Agent

Monitor water consumption and ETP load — a major sustainability lever

Inputs Flow meter readings, ETP inlet/outlet quality sensors, batch water usage logs
Logic Anomaly detection against per-batch water-usage baseline (liters/kg fabric)
Output {water_usage_anomaly, liters_per_kg, sustainability_flag}
Python Statistical Baseline
06
Agent
Predictive Maintenance

Predict machine breakdowns — looms, compressors, boilers — before they halt production

Inputs Vibration sensors, motor temperature, run-hours since last service
Logic Vibration signature classification (FFT features + classifier) to detect bearing wear, imbalance, misalignment
Output {machine_id, failure_probability, estimated_time_to_failure}
Python FFT scikit-learn CWRU Dataset
07
Agent
Defect Vision Agent

Classify fabric defects visually on the inspection line in real time

Inputs Camera feed / fabric images from inspection line
Logic CNN classifier detecting: hole, stain, slub, missing yarn, oil mark
Output {defect_type, confidence, location_on_roll}
PyTorch YOLOv8 MobileNet AITEX Dataset
08
Agent
Worker Safety Agent

Detect unsafe zones near moving machinery and PPE non-compliance

Inputs CCTV feed near looms/spinning frames
Logic Object detection (person + machine proximity) + PPE classifier (helmet/no-helmet)
Output {zone_id, violation_type, urgency}
YOLOv8 PPE Detection Roboflow
09
Agent
Traceability Agent

Track batch lineage — yarn lot → fabric roll — for quality recalls & certification

Inputs ERP/inventory records, batch IDs, QR/barcode scan logs
Logic Graph-based lineage tracking (yarn lot → loom → fabric roll → dye batch → finished roll)
Output {batch_id, full_lineage_graph, compliance_status}
Python Neo4j Graph DB
10
Brain
Orchestrator Agent — "The Brain"

Fuse all 9 specialist outputs into one Mill Health Score and one plain-language recommendation, resolving conflicts between competing priorities

Inputs Structured JSON outputs from all 9 specialist agents
Logic 1) Normalize risk scores to 0–1 scale 2) Weight by business impact 3) Detect conflicts (e.g., Energy vs Maintenance on same machine) 4) LLM reasoning for arbitration + natural-language output with cost estimate
Output {mill_health_score, top_risks[], recommended_action, estimated_savings, plain_language_summary}
Gemini API LangGraph Function Calling Supervisor Pattern
[ 03 ] System Architecture

Three-Layer
Intelligence

The floor manager never talks to 10 agents — they talk to one Orchestrator, which internally queries specialists the way a human plant manager would consult department heads.

Layer 1
Mill Floor
  • Spinning Sensors
  • Loom/Weaving Sensors
  • Dyeing Machine Sensors
  • Energy Meters
  • Water/ETP Sensors
  • Vibration/Thermal
  • Inspection Cameras
  • CCTV / Safety
  • ERP / Inventory
Layer 2
10 Specialist Agents
  • Yarn Quality Agent
  • Loom/Weaving Agent
  • Dyeing Consistency
  • Energy Optimization
  • Water & Effluent
  • Predictive Maintenance
  • Defect Vision
  • Worker Safety
  • Traceability
  • Orchestrator (Brain)
Layer 3
Unified Output
  • Mill Health Score (0–100)
  • Plain-Language Recommendation
  • Manager Dashboard
  • Chat Interface
  • Alert Notifications
  • Cost Impact Estimates
